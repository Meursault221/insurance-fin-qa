## 中国人保：从 A 股版换成 H 股版（已解决）

> 现状：**已解决**。下面是问题本身和怎么解决的，留档备查。

中国人保是 A+H 两地上市，两份年报出自不同排版流水线。

**A 股版**（巨潮资讯网 / 上交所，278 页）的问题是**数字压根没进文字层** ——
页面上的数字是矢量轮廓，`get_text()` 取不到，所以标签（"货币资金"）齐全，
数值全空：

```
中国人保 A股 第127页： 资产 / 货币资金 / 买入返售金融资产 / …
中国人寿   第89页：   货币资金 1 143,319 86,519 / 买入返售金融资产 2 50,879 30,560 / …
```

这类丢失**用"PDF 文字层 vs chunk"的比对发现不了** —— 两边都没有这些数字，
差异恒为空。只能反过来看数字密度：

| 文件 | 数字字符占文本比例 |
| --- | --- |
| 正常年报 | 0.074 ~ 0.129 |
| 中国人保 A 股版 | **0.001** |

**排查过程（没有用 OCR，也没有伪造任何数字）：**

1. 确认不是解析器的问题：PyMuPDF 与 pdfplumber 两个独立后端都取到 0 个数字。
2. 确认不是下载链路的问题：中国人保投资者关系官网发布的 PDF 与巨潮版本
   **逐字节相同**（sha256 一致），说明缺陷是**发布时就存在的**。
3. 转向 H 股版：港交所披露易 `2026042800675_c.pdf`（335 页）。
   它出自香港的排版流水线，文字层完整 —— 数字密度 0.070，
   合并利润表（第 182 页，244 个数字）、综合收益表（第 183 页，207 个）、
   财务状况表（第 184/185 页，222 / 247 个）、现金流量表（第 188/189 页，
   292 / 175 个）的数字全部可取。

**换版后核对**（`scripts/phase1_batch_report.py`）：

| | A 股版（旧） | H 股版（现用） |
| --- | --- | --- |
| 页数 | 278 | 335 |
| 数字密度 | 0.001 | 0.070 |
| 文字层无数字的页 | 136 | 0 |
| 关键财务数字可取 | ✗ | ✓（2,027,592 / 1,766,321 / 409,717 …） |

代价：两份报告**会计准则不同**（A 股版用中国企业会计准则，H 股版用
香港财务报告准则），部分科目口径与数值合法地不一样。引用时报告名标为
**《2025年年度報告（H股）》**，与 A 股口径的问题不要混答。

## 两个抽取缺陷（已修复，非中国人保独有）

排查中国人保时顺带发现两个会影响**所有公司**的缺陷：

**1. 数字被 span 边界劈开。** `_join_spans` 判断"上一个 span 是否以数字结尾"
时只要求最后一个字符是数字。中国人保 H 股年报把 `原保險保費收入27,383.33`
的 `2` 单独排成一个 6.4pt 的小 span（正文 11pt），于是判据成立、
在中间插了个空格，得到一个**根本不存在的数** `2 7,383.33`。
改成"上一个 span 必须以**完整**的千分位数收尾"后消除。
（原本要防的反向问题仍然防住：表格里 `376,112 | 1,304,712` 两列相邻，
不补空格就会粘成 `376,1121,304,712`，全库实测 32 处。）

**2. 港股年报的章节归属不可靠（未完全解决）。** 港股年报把**章节名印在每页
页眉**（如"管理層討論與分析""企業管治"），而 `_mark_running_headers`
会把跨页重复的页眉标成 `page_footer` 并排除出标题体系 —— 章节栈因此失去
了主要信号源。中国人保 H 股年报 695 个 chunk 里有 333 个的 section 是错的。

已经修掉的部分：标题词表补了繁体（`董事會報告`/`企業管治報告`/`第X節`），
并把"目录"挡在标题栈之外（它一旦入栈就再也不会被顶掉，因为它不是内容章节）。

**没做的部分**：让页眉驱动章节栈。实测 10 家公司的页眉后确认不能直接开 ——
页眉里混着非章节内容：中国人寿有 135 页顶着
"（除特别注明外，金额单位为人民币百万元）"，阳光保险 75 页是
"陽光保險集團股份有限公司 | 年年度報告"。需要一个更严格的过滤规则，
或改用年报自带的目录页来定章节。**港股 6 家的章节字段目前只能当参考。**
