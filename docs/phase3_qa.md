# 第三阶段设计说明：问答闭环

> 目标：**用户提问 → 混合检索 → 命中的年报片段交给大模型 → 答案带可追溯引用。**
> 引用至少包含公司名称、报告名称/年份、页码。

第二阶段已经解决了"从 7507 个 chunk 里找出相关的那几条"。第三阶段要在它上面
接一个能生成答案的模型，同时**不让它有机会编造数字和页码**。

代码分工：

| 文件 | 干什么 |
|---|---|
| `src/llm.py` | 材料拼装、提示词、HTTP 调用、引用核查。不认识 Retriever，可离线单测 |
| `src/qa.py` | 编排：检索 → 三层闸门 → 调模型 → 组装 `QAResult` |
| `web/app.py` | Streamlit 页面。没有任何检索或提示词逻辑 |
| `src/cli.py` 的 `ask` | 同一套流程的命令行版本，方便留痕和自动化 |

**检索逻辑一行没改。** `bm25.py` / `vector_index.py` / `hybrid.py` / `retriever.py`
在第三阶段只被调用，没被修改 —— 第二阶段的 229 个测试原样通过。

---

## 一、闭环长什么样

```
问题
 │
 ├─ Retriever.search()            第二阶段：混合召回（BM25 + 向量，RRF 融合）
 │                                公司过滤在打分前生效
 │
 ├─ 三层闸门                      材料够不够？（下面第三节）
 │   ① top-1 余弦 < 0.58  → 拒答，不调模型
 │   ② 问的年份材料里没有  → 拒答，不调模型
 │   ③ 提示词要求"材料没有就说没有"
 │
 ├─ build_materials()             只截尾、不改写。每条带公司/报告/页码/章节
 │
 ├─ LLMClient.complete()          POST 一段 JSON，取回一段 JSON（标准库 urllib）
 │
 └─ QAResult                      答案 + 引用 + 核查结果
      · cited_indexes              答案正文引用了哪几条材料
      · suspicious_pages          正文里出现、但材料中没有的页码 → 警告
      · sources                   原始 RetrievedChunk，引用块从它渲染
```

---

## 二、最关键的一条：引用不由模型生成

作业要求"答案必须能追溯到具体公司、报告、页码"，而大模型最容易出错的恰恰就是
页码。所以这里的做法是**把引用和答案彻底分开**：

- 模型只写答案**正文**，在正文里标材料编号 `[1]` `[2]`。
- 页面上展示的引用块，是程序用 `Chunk.citation()` 从 chunk 元数据渲染的。
  chunk 的 `company` / `report_name` / `page` / `section` 是第一阶段的 PDF 抽取器
  写进去的，**模型从头到尾碰不到**。
- 就算模型在正文里写"见第 999 页"，那个 999 也只会出现在正文里，
  不会变成引用块。而且 `find_suspicious_pages()` 会把它扫出来单独警告
  （`⚠️ 答案正文里出现了材料中没有的页码 [999] —— 可能是模型自己写的，请以引用区为准。`）。

**没有做静默删除。** 把编造的页码悄悄删掉，表面上干净，实际上掩盖了"这个模型
在编页码"这个事实。留着 + 标注，用户才知道要核对，我们也才知道模型靠不靠得住。

测试里专门有一组 `TestCitationsComeFromMetadata` 守住这条不变量。

## 三、三层闸门：什么时候不回答

作业要求"检索不到可靠资料就明说，不要编造"。只写一句"请勿编造"的提示词是不够的 ——
**实测发现单靠相似度根本分不开**：

| 问题 | top-1 余弦 |
|---|---|
| 中国平安**2026**年的净利润是多少？ | **0.736** |
| 题库里最简单的一道真题 | 0.629 |
| 美国 GDP 是多少？ | 0.529 |
| 比特币现在多少钱？ | 0.555 |

"2026年的净利润"余弦高达 0.736，**比最难的一道真题还高** —— 问法、指标名、
句式全都对得上，只是年份是未来。这类问题检索会返回 2025 年最像的段落，
模型看到"净利润"配上一堆真实数字，很容易顺手拿来答。**这是最危险的一类错误：
答案看起来有出处，数字也是真的，但答的是另一年。**

所以闸门分三层，各管一段：

### ① 相似度闸门（`MIN_COSINE = 0.58`）

top-1 余弦低于阈值直接拒答，**连模型都不调用**（省 token，也省得它硬编）。

阈值是标定出来的，不是拍的：题库 29 道真题的 top-1 余弦最低 0.629、中位 0.731；
8 个无关问题的余弦最高 0.555（比特币）。0.58 落在 0.555 和 0.629 中间，两边都留余量。

实测（`QA_MIN_COSINE` 可覆盖）：

| 问题 | top-1 余弦 | 结果 |
|---|---|---|
| 红烧肉怎么做才好吃？ | 0.296 | 拒答 |
| 推荐几本小说 | 0.332 | 拒答 |
| 今天天气怎么样？ | 0.404 | 拒答 |
| 量子纠缠是什么？ | 0.418 | 拒答 |
| Python 怎么读文件？ | 0.447 | 拒答 |
| 世界杯谁夺冠了？ | 0.452 | 拒答 |
| 美国 GDP 是多少？ | 0.529 | 拒答 |
| 比特币现在多少钱？ | 0.555 | 拒答 |
| **题库 29 道真题** | ≥0.629 | **全部放行 29/29** |

### ② 年份闸门（`check_year`）

问题里点名的年份，如果**既不是任何命中材料的报告年份、也没在材料正文里出现过**，
就拒答，并说清楚是年份对不上。这一层专门拦上面那个 0.736 的例子。

注意"没在材料正文里出现过"这一条不能省：问"2024 年的数据"是合理的，
因为年报正文里大量出现"较 2024 年增长 X%"这样的同比表述。

### ③ 提示词闸门

材料里确实没有的实体（比如"中国平安的 CEO 叫什么名字"），余弦可能并不低
（实测 0.653，检索到的是真实的相关段落），前两层拦不住。这一层靠系统提示词
要求模型明说"提供的材料不足以回答"。

**前三层都拦不住的情况确实存在** —— 这就是为什么还留了引用核查（第二节）。
多层防御，不指望任何单层完美。

### 拒答不是故障

拒答时页面用 `st.info` 展示（不是红色报错），文案明确说"因此不作答"，
并给改进建议（换问法、写全指标名、点名公司）。**更不会用模板拼一段假答案** ——
没配大模型时 `answer` 字段留空，只给检索结果和引用，而不是编一段话交差。

## 四、材料给的什么

每份材料长这样（`Material.header()`）：

```
[1] 公司：中国平安｜报告：2025年年度报告｜页码：364页｜章节：财务报表
正文：〔表格〕 | 附录：财务报表补充资料 | ...
```

几条刻意的取舍：

- **只截尾不截头**（默认 1200 字）。财报段落的关键数字常在前半部分，
  截头会把结论截掉。截断处写明"…（本段较长，已截断）"，
  免得模型把半截话当成完整结论。
- **正文原样拼接**，不做任何润色或数字格式化。千分位、单位（百万元/亿元）
  一律照抄。提示词里也明确要求不许换算、不许四舍五入。
- 材料条数默认 5。再多上下文变长，模型反而容易被无关段落带偏；再少可能漏掉关键那页。

## 五、大模型怎么接：不装 SDK

`ANTHROPIC_API_KEY` 和"OpenAI 兼容"这两种接口都只是「POST 一段 JSON、取回一段 JSON」，
用标准库 `urllib` 就够了。于是**第三阶段没有新增任何 LLM 依赖**：

- 少一个包少一份麻烦（本项目一直优先"Windows 下容易装、容易跑"）。
- DeepSeek / 通义 / 智谱 / Kimi / Ollama / vLLM 全都提供 OpenAI 兼容接口，
  换一个 `LLM_BASE_URL` 就能用，不用换代码、也不用再装东西。
- 将来要流式输出、重试、tool use 再换官方 SDK 也不迟。

key 从环境变量读，或写在项目根目录的 `.env`（模板见 `.env.example`）。
`load_env_file()` **只填 `os.environ` 里还没有的** —— 命令行显式设的优先；
返回值是变量名列表而**不是值**，免得 key 被打印进日志。
`LLMClient._guarded()` 是唯一出口，任何异常消息出栈前都过一遍 `_scrub()`，
保证 `LLMError` 的承诺（"消息里不含 API key"）真的成立。

### 验证方式

真实 API 调用要花钱，所以功能验证用的是**本地假接口**：起一个只有几十行的
stdlib HTTP server 冒充 `/v1/chat/completions`，把 `LLM_BASE_URL` 指过去，
跑一遍 `python -m src.cli ask`。确认了：

- 请求真的发到了 `{base}/chat/completions`，`Authorization: Bearer` 头正确；
- 提示词里确实带着 `公司：中国平安｜报告：2025年年度报告｜页码：364页`；
- 答案是模型返回的正文，引用块是程序渲染的；
- 答案里的 `[1][2]` 被正确解析成 `cited_indexes`，引用区标上了 `*`。

单元测试（`tests/test_qa.py`，65 个）用可替换的 `transport` 参数做到**完全不联网**。

## 六、数据完整性复核

第三阶段没有重新下载任何 PDF，直接复用第一阶段已经落盘的产物
（这是用户明确要求的：现有官方 PDF 可用就不重新下载）。

开工前复核了一遍，确认第二、三阶段用的索引和磁盘上的原文一致：

| 检查 | 结果 |
|---|---|
| 索引里的 chunk 正文 vs `data/chunks/*.jsonl` | **7507/7507 逐字节一致，0 条不一致** |
| 简繁归一前后数字串发生变化的 chunk | **0/7507** |
| 数字串总数 | 122,624 |
| 数字字符总数 | 443,532 |

第二项值得说明：**简繁归一（`zhconv`）只作用于分词和向量编码，不改 chunk 正文。**
5 家港股年报正文是繁体（占全部 chunk 的 52%），不转换的话简体提问
"总资产"永远匹配不上原文的"總資產"。但转换只发生在 token 层 ——
索引里存的、页面上显示的、引用块里引的，始终是 PDF 里那个原文。

## 七、已知局限

- **`top_k` 直接决定"答得出来多少"。** 送给模型的材料条数就是召回上限：
  在 29 道真题上实测，`-k 5`（页面默认）召回 gold 页码 **22/29**，
  `-k 10`（第二阶段评测的口径）**26/29**。另外 3 道题（q13/q20/q29）
  在 top-10 里也召回不到，那是第二阶段的已知局限，第三阶段不解决。
  想要覆盖更全就把侧栏的"送给模型的片段数"调大，代价是上下文变长、
  无关段落也更多。
- **拒答阈值是标定出来的，不是普适的。** 0.58 是在"29 道真题 + 8 个无关问题"
  这个样本上定的。换题库、换向量模型都要重新标定（`QA_MIN_COSINE` 可覆盖）。
- **相似度和年份都拦不住"实体缺失"类问题。** "中国平安的 CEO 是谁"余弦 0.653，
  检索到的是真实的相关段落，前两层放行，只能靠提示词让模型自己说"材料里没有"。
  这类问题需要人工核对，或者在检索层做实体覆盖检查（第三阶段没做）。
- **材料截断可能截掉关键数字。** 1200 字的限制对绝大多数 chunk 够用，
  但财报里有整页的合并报表，关键行可能在 1200 字之后。目前只截尾不截头，
  是对"关键信息在前半段"这个经验规律的赌注。
- **模型仍可能算错。** 提示词要求"不许换算、不许四舍五入"，
  但模型自己做的加总/占比计算仍可能出错。引用块能证明**数字来自哪一页**，
  不能证明**模型算对了**。
- **一次只答一个问题。** 不支持多轮对话，每个问题独立检索。
- **`suspicious_pages` 是提示不是保证。** 它只扫"第 X 页"和"X 页"两种写法，
  模型用别的措辞提页码就扫不到。

## 九、怎么跑

```bash
# 页面（推荐）
streamlit run web/app.py          # → http://localhost:8501

# 命令行（留痕用）
python -m src.cli ask "中国平安2025年归属于母公司股东的净利润是多少？" -k 5 --show-text 120

# 看实际送给模型的材料，排查"为什么答错了"
python -m src.cli ask "问题" --show-materials

# 只看检索、不生成（对比用）
python -m src.cli search "问题" -k 5 --show-text 120
```

没配 `.env` 也能跑 —— 页面会正常显示检索结果和引用，只是不生成答案正文。
