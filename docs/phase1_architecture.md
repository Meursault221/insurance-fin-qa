# 第一阶段设计说明

> 目标：把一份年报 PDF 变成「每条都带完整来源信息的检索单元」。
> 这一阶段的产出物是 `data/extracted/*.json` 和 `data/chunks/*.jsonl`，
> 它们是第二、三阶段唯一的输入。

---

## 一、数据流

```
data/raw/xxx.pdf
      │
      │  ① pdf_extractor.extract_pdf()
      │     逐页：文本行 → 段落/标题 → 表格 → 章节归属 → 页脚页码
      ▼
ExtractedDocument             (data/extracted/xxx.json)
      │  meta  : 公司 / 报告名 / 年份 / 股票代码 / 源文件指纹
      │  pages : 每页的 blocks(文本) + tables(表格) + printed_page
      │
      │  ② chunker.chunk_document()
      │     按页、按章节聚合；表格原子化；句末断句
      ▼
list[Chunk]                   (data/chunks/xxx.jsonl)
      │  company / report_year / report_name / page / section / text
      │  + tables(cells 二维数组) / context_prefix / chunk_id
      ▼
   [第二阶段] BM25 索引 + 向量索引
```

---

## 二、PDF 解析

### 依赖选择

| 方案 | 结论 |
|---|---|
| **PyMuPDF** | ✅ 主方案。纯 wheel，Windows 装上就能用，速度快，能拿字号/字体/坐标，自带 `find_tables()` |
| **pdfplumber** | ✅ 备用表格后端。纯 Python，对有框线的财报表格识别往往更稳，但慢 5~10 倍 |
| camelot / tabula | ❌ 需要 Java 或 Ghostscript，Windows 上部署很折腾 |
| pdfminer.six | ❌ 只抽文本，拿不到字号，标题识别没法做 |

两个后端产出**同一种** `TableBlock`，`--table-backend` 一键切换。
在合成样本上两者结果完全一致（表格数、正文字符数、单元格数都相同）。

### 逐页处理步骤

1. `page.get_text("dict", sort=True)` 拿到所有文本行，带 bbox / 字号 / 字体 / bold 标记
2. **推断正文字号**：按字符数加权取众数（用前 30 页做样本）。这是标题识别的基准
3. **行 → 段落**：同一 block 编号、字号相近、垂直间距小的行合并成一段
4. **表格抽取**：`page.find_tables()`（或 pdfplumber）
5. **标题识别 + 章节路径**（见下）
6. **标记表格区域内的文本块**：中心点落在表格 bbox 内的，标成 `kind="table_text"`
   —— **保留不删**，由切分层决定是否收录
7. **页脚页码识别**：看页面最后 3 个块，整行是 `12` / `第 12 页` 这种就记为 `printed_page`

## 三、标题识别（`src/sections.py`）

中文年报的层级：

```
第三节 管理层讨论与分析          level 1
（一）主要财务数据               level 2
1. 营业收入                      level 3
1.1.1 分险种明细                 level 4
```

判定顺序：

1. **编号正则**：`第X节` → 1；`（一）`/`一、` → 2；`1.1` → 3；`1.1.1` → 4
2. **兜底**：字号 ≥ 正文 1.30 倍 → 1；≥ 1.12 倍或加粗 → 2

### 踩过的坑：数字密度误杀

最初的实现用「数字字符占比 > 35% 就判定为数据行」来排除
`1,234.56  1,111.00  11.1` 这类表格行。
结果 `1.1.1 详细说明` 被误判成正文 —— 因为编号本身就占了 5/10 个字符。

修法：**先剥掉编号前缀，只对剩下的正文算数字密度**；
并且要求剥掉编号后必须还剩有实际文字
（这样 `1.23`、`(1,234)` 这种纯数字仍然被正确排除）。

### 章节路径

用一个标题栈维护，遇到低层级标题就弹出栈顶：

```
heading(1, "第三节 管理层讨论与分析")  → "第三节 管理层讨论与分析"
heading(2, "（一）主要财务数据")       → "第三节 ... > （一）主要财务数据"
heading(1, "第四节 公司治理")          → "第四节 公司治理"     ← 二级标题被弹出
paragraph("本集团2025年……")           → 沿用栈顶路径
```

## 四、表格处理

### 线性化

二维单元格 → markdown 管道表，**逐字符搬运**：

```
| 项目 | 2025年 | 2024年 | 变动(%) |
| --- | --- | --- | --- |
| 示例营业收入 | 1,234 | 1,111 | 11.1 |
```

- 千分位逗号、负号、括号负数、百分号 **原样保留**
- 空单元格（`None`）渲染成空字符串，**不填 0**
- 单元格内的 `|` 转义成 `\|`，防止破坏表格结构
- 行宽不齐时补齐空串（不是 0）

### 表头去重

PyMuPDF 的 `tab.extract()` 返回的 `cells` **包含表头行**，
而 `tab.header.names` 也是表头。直接拼会渲染两遍：

```
| 项目 | 2025年 |        ← 来自 header
| --- | --- |
| 项目 | 2025年 |        ← 来自 cells[0]，重复！
| 营业收入 | 1,234 |
```

修法：`cells[0]` 与 `header` 内容一致时才丢弃首行
（用一致性检查而不是无条件丢弃，避免误删真正的数据行）。

### 表格的章节归属

表格是独立于文本块抽出来的，需要单独判断它属于哪一节。

**踩过的坑**：一开始直接取 `tracker.current`，但那是在整页所有
文本块都处理完之后的状态 —— 拿到的是**该页最后一节**的标题。

修法：新增 `_section_at_y(blocks, y)`，按表格的纵坐标找它**上方最近**的那个
文本块所属的章节。

### 表格题注

表格上方最近的短文本块（含"单位"，或长度 ≤ 25 字）作为题注。
限制"含单位或很短"是为了避免把表格上方的一整段正文误当标题 ——
一开始没这个限制，抓到一个孤零零的 `。` 当题注。

## 五、切分策略（`src/chunker.py`）

| 规则 | 理由 |
|---|---|
| **表格原子化** | 一张表一个 chunk，绝不切开。财报表格劈开 = 数字对不上科目，检索回来也没用 |
| **不跨页** | `page_end == page`，页码字段永远精确。代价是段落可能被页边界截断，换来引用绝对可信 |
| **标题有条件开新块** | 只有缓冲已攒够 `min_chars` 时才另起一块。年报小标题极多，逢标题就断会产生一堆几十字的碎块 |
| **句末优先断句** | 达到上限时往回找最近的 `。；！？` 或换行，不硬切在字中间 |
| **短尾合并** | 同页同章节的 < 120 字碎块并入前一块 |

### `block_type` 字段

一个 chunk 里可能混了标题和正文，所以用集合记录：

- 只有标题 → `heading`
- 只有正文 → `paragraph`
- 只有表格 → `table`
- 标题+正文混在一起 → `mixed`

（早期实现里标题开了新块后 `buf_type` 一直保持 `heading`，
导致"标题+正文"的块被标成 `heading`，已经修掉。）

## 六、数据结构

### `Chunk`（`data/chunks/*.jsonl` 的每一行）

作业要求的五个来源字段：

| 字段 | 示例 |
|---|---|
| `company` | `中国平安` |
| `report_year` | `2025` |
| `report_name` | `2025年年度报告` |
| `page` | `12` |
| `section` | `第三节 管理层讨论与分析 > （一）主要财务数据` |
| `text` | 正文 |

附加溯源与检索字段：

| 字段 | 用途 |
|---|---|
| `chunk_id` | `pingan_2025_annual_p0012_c0003`，含页码，可读且唯一 |
| `doc_id` | 指向 `data/extracted/<doc_id>.json` |
| `page_end` | 跨页 chunk 的结束页（当前策略下恒等于 `page`） |
| `printed_page` | 页脚印刷页码 |
| `block_type` | `paragraph` / `table` / `heading` / `mixed` |
| `tables` | 内嵌的 `cells` 二维数组，供第二阶段精确取数 |
| `context_prefix` | `【中国平安·2025年年度报告】第12页 第三节 …`，拼在正文前喂 embedding |
| `stock_codes` | `["601318.SH", "2318.HK"]` |
| `source_file` | 原始 PDF 文件名 |

`Chunk.embed_text` 属性返回 `context_prefix + text`（**只用于向量化**）；
`Chunk.text` 是不带前缀的干净正文，**展示给用户时用这个**。

## 八、已知限制

1. **扫描件抽不出文字**。检测到「页面字符数 < 40 但有图片」会记进
   `stats.scanned_pages` 并告警。这类报告需要先 OCR。
2. **复杂合并单元格可能错位**。跨行跨列的表头 `warnings` 会提示
   "可能存在合并单元格"，需要人工核对。
3. **页眉未去除**。目前只识别页码型页脚，公司名页眉可能残留在正文里。
4. **印刷页码 vs 物理页号未做映射**。两个都存了，引用统一用物理页号。
5. **纯英文年报**的标题识别只靠字号规则，不如中文的编号规则可靠。
